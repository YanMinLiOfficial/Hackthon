# MVP 开发规则

- 开发前必须确认用户在当前对话中明确声明了成员身份，以及当前操作系统和终端。
- 若任一信息缺失，必须先询问“你是哪个成员？当前使用什么操作系统和终端？”，得到回答前不得修改任何文件；不能仅凭分支、路径或历史对话推断。
- 根据成员身份从 `TEAM_PLAN.md` 自动确定负责模块和分支，不再向用户询问这两项；当前分支不符时应指出并切换。
- 确认身份后，阅读根目录 `AGENTS.md`、`TRAE_MVP_PROMPT.md`、`TEAM_PLAN.md` 和 `TASKS.md`。
- 当前任务以 `TASKS.md` 为准，产品定义和验收标准以 `TRAE_MVP_PROMPT.md` 为准。
- 优先贯通一条可演示的纵向闭环，不先创建大量空页面或提前抽象。
- 使用本地模拟数据和 `localStorage`；除非用户明确要求，不接真实后端或付费 API。
- 所有 AI、导航、标准条款、通知和隐私处理的模拟结果必须在界面中明确标注。
- 每个地点只保留一个地图大头针，多次观察进入地点时间线。
- 主要流程必须支持键盘操作、清晰焦点、非颜色状态提示、大字和高对比度。
- 新增依赖前先检查现有依赖；采用最简单、稳定、可离线演示的方案。
- 按 `TEAM_PLAN.md` 的模块边界工作，不擅自改动其他成员的共享接口。
- 命令和路径必须适配当前成员的 macOS/zsh 或 Windows/PowerShell 环境；项目脚本本身必须保持跨平台。
- 使用短生命周期功能分支；每个提交只处理一个可解释、可回退的目的，避免一次提交大段无关代码。
- 开始任务、创建 PR 和合并前同步最新 `main`；共享接口变更必须先由项目负责人确认并单独提交。
- 提交前检查 diff，只暂存当前任务文件；禁止重写他人历史、强推共享分支或混入全仓格式化。
- 完成任务后更新 `TASKS.md`，交付前运行 `npm run build` 并修复错误。
- 只有会改变核心闭环、数据真实性或验收标准的决策才向用户确认。
